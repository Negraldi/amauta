## Activation Contract

Load this skill for presentations, reports, documents and dashboards whose readers decide something. Pair it with
`institutional-presentation` for a deck, `powerbi-report` for a report and `doc-formats` for the file mechanics.

## Hard Rules

- Before drafting, establish the audience, the decision, the supported claim, and its source, period, population and
  denominator. For a metric add its update cadence, freshness limit and unavailable state.
- Missing information gets an explicit pending marker. Never infer a business fact or a permission to use a source.
- Brand (logo, palette, fonts, templates) comes from the project's selected profile; with no profile, stay neutral.
  Never copy an organization's assets into a shared repository.
- Synthetic examples say so on the page and are never reused as evidence.
- Publishing, sending and changing shared spaces are separate actions the user authorizes.

## Page or slide structure

1. A title that states the supported conclusion or the decision question.
2. One principal idea per view: a table for exact values, a chart for patterns or comparisons.
3. Units beside numbers; counts, percentage changes and percentage-point changes kept apart.
4. Source, period, population and denominator next to the claim or in an evidence note.
5. Observations, interpretation and recommendations separated; estimates and assumptions labeled. A correlation is not
   a cause.

## Delivery check

Check legibility in the target format at the agreed minimum size (1366 x 768 for screens). Verify every quantity
against its source and scope; remove an unsupported claim or keep the draft marked as draft. Opening a desktop
application to look at the result needs the user's permission. Keep the editable source and say which checks did not
run.
