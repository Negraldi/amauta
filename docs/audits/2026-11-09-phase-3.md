## Deviations recorded

- S1 was planned as "links and health" of two sibling projects. After the review of the user's local orchestrator it
  became a real execution feature inside amauta (ADR 0010); `harness-pipelines` is no longer needed. `oga_catalog`
  stays a sibling with a generic health card (user decision 2026-11-09).
- Two CI failures on the branch: `8199314` pushed the Windows tests alone to see them fail there first (RED by
  design); `5632b85` failed one macOS test whose fixture used the same `ps` prefix as macOS itself (test fixed in
  `2c4c1b5`, no code change).
- Concurrency fixes without a deterministic test (a guarded adopt, the portal's bookkeeping under a mutex, a job
  without kill-on-close not used) are listed as such in `odd/tasks/pipelines-hardening.md`.

## Private content search

`git grep` over every tracked file except vendored upstream code: no word from the user's organization, servers,
databases, people or brand colors found in the orchestrator archive or the corporate harness (checked with word
boundaries), no IPv4 address other than loopback (one false hit inside an SVG path), no e-mail address other than
synthetic fixtures. The orchestrator archive and the corporate harness were read in the session's scratch folder only;
the explainer page and the docs use synthetic examples.

## Limits kept, documented in docs/pipelines.md

- Steps run with the user's permissions and inherit the starting environment; amauta does not isolate them.
- If the runner is killed outright, the step running at that moment keeps running; the run reads as abandoned.
- A process that leaves a step's group on purpose and holds its output is given up on after two seconds and keeps
  running.
